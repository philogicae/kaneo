title: Nginx

## Overview

This fork runs as one container that already serves the web app and proxies `/api` requests internally, so Nginx only needs a single server block pointing at port `5173`. There is no separate API service to expose.

## Prerequisites

- A domain name pointing at the server
- An Nginx web server

```bash
sudo apt update
sudo apt install nginx
```

## Configuration

Create `/etc/nginx/sites-available/kaneo.conf`:

```nginx title="kaneo.conf"
server {
  listen 80;
  server_name kaneo.your-domain.com;

  location / {
    proxy_pass http://localhost:5173;
    proxy_http_version 1.1;

    # WebSocket upgrade for the realtime board and task updates.
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    client_max_body_size 20m;
  }
}
```

Enable it and reload Nginx:

```bash
sudo ln -s /etc/nginx/sites-available/kaneo.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

## TLS

Add certificates with certbot, which rewrites the server block for HTTPS:

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d kaneo.your-domain.com
```

## Set the public URL

Set `KANEO_CLIENT_URL=https://kaneo.your-domain.com` in `.env` (and recreate the container) so links in notifications, emails, and the MCP `get_public_url` tool use the public address. See [environment variables](/core/installation/environment-variables).

## Notes

- If you run the API directly on the host during development instead of the container, it listens on `1337` and Vite on `5173`; production deployments only need `5173`.
- Realtime updates use the in-process broadcast adapter, so this fork runs as a single API instance; there is no Redis adapter to scale it horizontally.
