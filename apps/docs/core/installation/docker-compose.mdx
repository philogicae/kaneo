## The compose file

This fork ships as one container: the bundled API and web app, with the libSQL (Turso) database stored on a local file. There is no PostgreSQL service.

`compose.yml` builds the image from `Dockerfile.kaneo`:

```yaml
name: kaneo

services:
  kaneo:
    container_name: kaneo
    build:
      context: .
      dockerfile: Dockerfile.kaneo
    image: kaneo-custom
    init: true
    restart: unless-stopped
    ports:
      - "5173:5173"
    env_file:
      - .env
    volumes:
      - ${KANEO_DATA_PATH:-./data}:/app/data
    healthcheck:
      test:
        [
          "CMD",
          "wget",
          "--no-verbose",
          "--tries=1",
          "--spider",
          "http://127.0.0.1:5173/api/health",
        ]
      interval: 30s
      timeout: 5s
      start_period: 60s
      retries: 3
```

Start it with:

```bash
cp .env.sample .env
# Set KANEO_CLIENT_URL and AUTH_SECRET at minimum
mkdir -p ./data && chown -R 1001:1001 ./data
docker compose up -d --build
```


## Services and volumes

- `kaneo`: the API and web app in one container, exposed on port 5173.
- `${KANEO_DATA_PATH:-./data}` bind-mounted at `/app/data`: holds the libSQL database file (`kaneo.db`) and its WAL/SHM sidecars. The directory must be writable by the container user (uid 1001).

## Required configuration

Copy `.env.sample` to `.env` and set:

```env
KANEO_CLIENT_URL=http://localhost:5173
AUTH_SECRET=                             # generate: openssl rand -hex 32
```

`KANEO_API_URL` defaults to `KANEO_CLIENT_URL/api`. This keeps the browser on one origin while the container proxies `/api` requests to the internal API process.

## Assets and uploads

Image and file uploads in task descriptions and comments are stored on local disk under the data volume (`/app/data/assets` by default) — no object-storage service is required. The directory is created automatically; override it with `STORAGE_PATH` (keep it inside a mounted path) or cap sizes with `STORAGE_MAX_IMAGE_UPLOAD_BYTES`. See [Image uploads and asset storage](/core/installation/object-storage-and-image-uploads).

## 3. Start the container

```bash
docker compose up -d
docker compose ps
curl --fail http://localhost:5173/api/health
```

Allow time for the first database initialization and migrations. The service should become healthy. If it does not, check:

```bash
docker compose logs --tail=100 kaneo
```

Open [localhost:5173](http://localhost:5173), create the initial account, and follow [Your first project](/core/index).

## 4. Make it available to your team

The port is bound to the host's loopback address. To serve Kaneo on a domain, follow the [Nginx and HTTPS guide](/core/reverse-proxy/nginx), then set:

```env
KANEO_CLIENT_URL=https://kaneo.example.com
```

Apply environment changes by recreating the container:

```bash
docker compose up -d --force-recreate kaneo
```

A plain restart keeps the old environment. If you use a proxy in another container, connect it to Kaneo's Docker network and proxy to `kaneo:5173` instead of the host's loopback address.

## Keep secrets in files

Instead of putting `AUTH_SECRET` in `.env`, you can mount it as a Docker secret file. This requires a Kaneo release that includes `_FILE` support, so raise `KANEO_IMAGE_TAG` past `2.28.3` first.

Move the value you already use from `.env` into its own file:

```bash
mkdir -p secrets
sed -n 's/^AUTH_SECRET=//p' .env > secrets/auth_secret
chmod 700 secrets
chmod 644 secrets/auth_secret
```

Keep the current value: a new `AUTH_SECRET` would sign everyone out. Generate a fresh one with `openssl rand -hex 32` only for an installation that has not started yet.

Compose mounts the file with its host ownership, and the container reads it as a non-root user (UID 1001). The file therefore needs to be readable by other users, while the `700` directory keeps other accounts on the host from reaching it.

Remove `AUTH_SECRET` from `.env`. In `compose.yml`, add the secret to the `kaneo` service:

```yaml
services:
  kaneo:
    environment:
      AUTH_SECRET_FILE: /run/secrets/auth_secret
    secrets:
      - auth_secret

secrets:
  auth_secret:
    file: ./secrets/auth_secret
```

Keep the other keys of the service as they are. For [custom OAuth](/core/social-providers/custom-oauth), mount the client secret the same way and set `CUSTOM_OAUTH_CLIENT_SECRET_FILE`. A direct value in `.env` takes precedence over its `_FILE` variable, so leave the direct variable unset. See the [environment variable reference](/core/installation/environment-variables#authentication) for how files are read and what happens when one is missing.

## Optional features

- [SMTP](/core/installation/environment-variables#smtp-configuration) delivers sign-in codes, invitations, and notifications.
- [Sign-in providers](/core/social-providers/custom-oauth) connect your identity provider.

The database file lives in the data volume, not in an external service. Back up the `${KANEO_DATA_PATH:-./data}` directory before storing work you care about; see [backups](/core/operations/backups) and the [upgrade guide](/core/operations/upgrades).
