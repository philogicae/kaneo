## Overview

Kaneo supports private uploads in task descriptions and task comments:

- images render inline in the editor and in task views
- other files such as CSV, PDF, or ZIP appear as attachment cards and links
- every file is private and served back through the API (`/api/asset/{id}`), never from a public URL — except for assets that belong to a [public project](/core/functional/collaborate-with-team), which the download route serves without a session

No object-storage service is required: files are written to the local disk.

## Where files live

By default uploads go to `assets/`, next to the database file:

| Deployment | Location |
| --- | --- |
| Docker Compose | `/app/data/assets` inside the container, on the `${KANEO_DATA_PATH:-./data}` bind mount |
| Local `pnpm dev` | `<repo>/data/assets` |

The directory is created automatically. Override it with `STORAGE_PATH` — if you point it outside the data volume, mount that path too or uploads disappear when the container is recreated. `STORAGE_KEY_PREFIX` optionally prefixes every stored key.

Object keys are structured per workspace, project, task, and surface:

```
workspace/<workspace-id>/project/<project-id>/task/<task-id>/descriptions|comments/<name>-<timestamp>-<id>.<ext>
```

Because the files sit on the same volume as the database, one backup of the data directory covers both.

## How uploads work

1. The editor asks the API for an upload slot for a task and a surface (`description` or `comment`).
2. The browser PUTs the bytes to the API's own upload endpoint.
3. The API records a private asset row and the editor inserts `/api/asset/{id}` into the text.
4. Kaneo serves the file back through the API with the requester's access rights; an upload key only works for the task and surface it was issued for.

Uploads are capped by `STORAGE_MAX_IMAGE_UPLOAD_BYTES` (default 10 MB). See [environment variables](/core/installation/environment-variables) for the full list.

## Backups

Uploaded files are part of the data directory. Stop the container (or checkpoint the database) before copying:

```
data/
├── kaneo.db
├── kaneo.db-wal
├── kaneo.db-shm
└── assets/
```
