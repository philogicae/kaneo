Kaneo ships a built-in MCP (Model Context Protocol) endpoint: every instance exposes `/api/mcp` out of the box. No extra process, no extra package — clients connect over Streamable HTTP directly to your instance.

> Upstream Kaneo also publishes a stdio npm package ([`@kaneo/mcp`](https://www.npmjs.com/package/@kaneo/mcp)) for clients that only support stdio transport. This fork's documentation covers the built-in HTTP endpoint, which is what the instance uses. See the [upstream docs](https://kaneo.app/docs/core/integrations/mcp) for the stdio package.

## Built-in HTTP endpoint

Point your MCP client at:

```
https://your-kaneo-instance.com/api/mcp
```

On first connect, you will be redirected to Kaneo to sign in and explicitly approve the MCP client. After approval, all MCP tools run as your authenticated user.

The endpoint implements OAuth 2.1 with PKCE for authentication. Discovery metadata is available at:

- `/.well-known/oauth-protected-resource/api/mcp`
- `/.well-known/oauth-authorization-server/api`

### API key authentication

Clients that cannot run the OAuth consent flow can authenticate with an [API key](/api-reference/authentication) instead. Send the key either as a bearer token or in the `x-api-key` header:

```http
Authorization: Bearer <api-key>
```

```http
x-api-key: <api-key>
```

The MCP tools then call the Kaneo API with the same key, so the key's workspace access applies exactly as it does for the REST API. Revoking the key in Settings → Account → Developer immediately revokes MCP access.

The endpoint serves both MCP protocol eras: modern `2026-07-28` requests are
stateless and self-contained, while 2025-era clients keep the sessionful
`initialize` flow. See [MCP 2026-07-28 stateless compatibility](/core/integrations/mcp-stateless)
for the exact contract, tests, Codex configuration, limitations, and rollback.

## Available tools

The HTTP endpoint exposes these tools:

- Session: `whoami`, `list_workspaces`, `list_workspace_members`, `list_notifications`
- Search: `search`
- Projects: `list_projects`, `get_project`, `create_project`, `update_project`, `list_project_columns`
- Columns: `create_column`, `update_column`, `reorder_columns`, `delete_column`
- Tasks: `list_tasks`, `get_task`, `create_task`, `update_task`, `delete_task`, `move_task`, `update_task_status`, `update_task_assignee`, `update_task_due_date`, `list_task_activity`
- Bulk tasks: `bulk_update_tasks`
- Time entries: `list_task_time_entries`, `get_time_entry`, `create_time_entry`, `update_time_entry`
- Comments: `list_task_comments`, `create_task_comment`
- Labels: `list_workspace_labels`, `create_label`, `attach_label_to_task`, `detach_label_from_task`, `delete_label`
- Task relations: `create_task_relation`, `get_task_relations`, `delete_task_relation`

`list_project_columns` is worth calling first when setting a status: the column
slugs it returns are exactly the values `create_task` and `update_task_status`
accept. Likewise `list_workspace_members` resolves the user IDs the assignee
tools expect. Time entries have no delete endpoint on the API, so there is no
`delete_time_entry` tool. `bulk_update_tasks` applies one operation to many
tasks at once, which is the cheapest way to triage a backlog, calendar, or
Gantt selection.

## Debugging

Check that the endpoint responds and discovery metadata resolves:

```bash
curl -i https://your-kaneo-instance.com/.well-known/oauth-protected-resource/api/mcp
```

A `401` from `/api/mcp` without credentials is expected; a `404` usually means the reverse proxy in front of the instance does not forward the `/.well-known` paths or the `/api/mcp` route. Authentication failures with API keys most often mean the key was revoked or lacks workspace access — regenerate it in Settings → Account → Developer.
